03

Scope

What Mode C is, and what we are testing

Mode C is the observation regime where the receiver provides per-element snapshots, so the algorithm can build a spatial covariance matrix. It is the richer of the two regimes in this milestone — Mode S sees only a scalar SINR reading — and it is where the classical adaptive-array literature applies directly.

Scope is deliberately narrow: one jammer, unknown direction, drifting slowly, in 2-D (θ, φ), with real CST-exported element patterns.

Algorithms may consume only the snapshots. The true jammer angle never leaves the simulator.

SINR(w) = σ_s²|wᴴe_s|² / (σ_j²|wᴴe_j|² + σ_n²‖w‖²)

Each element is multiplied by a complex weight and summed. The whole problem is choosing those weights, in real time, from measurements alone — keeping gain on the target while placing a null on a jammer nobody told you about.

04

The algorithms

Four algorithms, chosen to bracket the problem

AlgorithmWhat it knowsWhy it is in the suite
oracleTrue jammer angle + covariance Perfect-knowledge upper bound. Scores 100 by construction — a free sanity anchor on every grid.
lcmvMeasured covariance only The shipped reactive baseline. Classical MVDR — the standard any adaptive nuller must beat.
predict+ a MUSIC angle estimate Explicit jammer direction, so a null can be placed before energy returns. Built for on/off jammers.
predict + CV+ a motion model New. Aims where the jammer will be, not where it was.

They are not four attempts at the same thing. oracle sets the ceiling, lcmv is the incumbent, and the other two each add exactly one new piece of knowledge — an angle, then a velocity — so any gain is attributable.

05

How it works

The reactive nuller needs no idea where the jammer is

Minimise total output power, subject to holding unit gain on the target direction:

w = R⁻¹e(θ_s) / (e(θ_s)ᴴR⁻¹e(θ_s))

Any strong source that is not the target gets suppressed automatically — because suppressing it is what minimises output power. That is the elegance of the classical solution, and why it is the baseline.

The covariance is estimated from snapshots with exponential forgetting:

R̂(t) = λ R̂(t−1) + (1−λ) x xᴴ

λ = 0.90, so the estimate averages roughly the last 10 steps.

That forgetting is the entire story of what follows. It is what makes the array adaptive, and it is what makes it late.

Method

One number per cell, normalised against the achievable

track_score = 100 · mean( (SINR_oracle − SINR) ≤ 3 dB )

The fraction of the run spent within 3 dB of the perfect-knowledge beamformer. Because it is normalised against what is achievable, cells at different angles, arrays and power levels are directly comparable — which raw availability is not, since it saturates at 100% across every easy cell. It folds convergence speed, steady-state gap and recovery into one figure. Pass mark 90.

08

Result 2 — diagnosis

The tracker is aiming one covariance horizon into the past

Two consequences. The deficit is an angle-lag deficit, so an angle predictor is the matching fix — and re-tuning λ is not, which agrees with the earlier sweep that found no λ where the failing cells pass. And the realistic target is ~95%, not 100%.

09

Result 2 — the lag budget

The lead is derived, not tuned

MUSIC is computed from the same exponentially-forgotten covariance, so it inherits the same lag. Measured directly, the raw MUSIC angle best matches truth delayed exactly 10 steps — mean error 0.27° at τ=10, rising either side.

lead = 10 (covariance) + 4 (application) = 14

This gives a design rule rather than a magic number: the lead should track 1/(1−λ), and must be re-tuned if λ moves.

10

Result 3 — the fix

A constant-velocity tracker on the jammer's angle

A Kalman filter on [θ, θ̇, φ, φ̇], fed by the MUSIC angle the algorithm already computes, extrapolated 14 steps ahead. While the jammer is both detected and moving, the null is aimed at the predicted angle.

Result 4 — the real constraint

Calibration, not drift, is what limits fielding

  • Usable region is below ~1° RMS per-element phase error; by 3° everything is at the floor.
  • The spread is enormous — at 2° the p10–p90 range is 1.1–76.8. One array build could be fine and the next unusable.
  • This exposure is unchanged by the predictor, which keeps its 2–4× advantage throughout.
13

Two findings we were not looking for

An array that cannot tell up from down

F1

ManyDipoles is exactly mirror-degenerate: e(θ,φ) ≡ e(180−θ,φ), steering coherence 1.0000. That is the textbook up/down ambiguity of a planar array with no geometric phase re-added — real physics, not a bug.

It is benign for nulling (identical steering vectors mean a null at the mirror is the null at truth) but fatal for tracking. The filter now detects each array's own degeneracy and folds measurements to the nearer branch.

Measured modulo the fold, the DoA error drops from median 139° to 1.5°.

F2

A previous note had retracted a front/back-ambiguity diagnosis, on the grounds that this array has the lowest antipodal coherence of the three.

That is true — but the antipodal pair is (180−θ, φ+180), and the real degeneracy is (180−θ, φ). A different pair.

The ambiguity was real; the measurement that dismissed it was aimed at the wrong angles. This also closes an open item: the DoA front-end had never been tested on real element patterns. It works.
