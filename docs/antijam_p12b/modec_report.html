Anti-jam milestone · Phase P12b · 2026-09-07

Mode C anti-jam: what works, what doesn't, and what ships

A test campaign on the covariance-domain anti-jam stack. It diagnoses the drift failure P12 left open, fixes it with a constant-velocity DoA predictor, and finds that the constraint on fielding this is array calibration — not the algorithm.

Branch antijam-p10-freq-notch Runs 2,034 closed-loop, 0 failed case-seeds Arrays 3 Gates 53/53 anti-jam MATLAB R2026a, R2020a-compatible

Verdict

01

The drift failure is real, diagnosed, and fixed

The shipped tracker passes 2 of 15 drifting-jammer cells. The cause is angle lag of exactly one covariance horizon. A constant-velocity DoA predictor takes it to 11 of 15 (mean score 55.2 → 90.3), while leaving static and on/off cases bit-identical.

02

Calibration, not drift, is the binding constraint on delivery

Made measurable for the first time this phase. The stack needs per-element phase calibration better than ~1° RMS; by 3° every algorithm is at the floor. This is a larger risk than the gap just closed, and nothing in the design measures or corrects it.

03

The old headline metric would have hidden all of this

The 35-point tracking gain shows up as +0.05 pp of availability (98.18 → 98.23). Availability saturates on easy cells and cannot rank algorithms. Every number here is the oracle-tracking score instead.

What is being tested

Mode C is the observation regime where the receiver gives per-element snapshots, so the algorithm can form a spatial covariance matrix. That is the richer of the two regimes in this milestone — Mode S sees only a scalar SINR reading — and it is where the classical adaptive-array literature applies directly. Scope is one jammer, unknown direction, drifting slowly, in 2-D (θ, φ).

The four algorithms, and why these

Each earns its place by answering a different question, so the set brackets the problem rather than sampling it.

Mode C algorithms under test. oracle is not a competitor — it defines the reference every score is measured against.

How the reactive nuller works

An adaptive array multiplies each element by a complex weight and sums. Choosing the weights w to minimise total output power subject to holding unit gain on the target direction gives the classical solution:

w = R⁻¹e(θ_s) / ( e(θ_s)ᴴ R⁻¹ e(θ_s) )

Any strong source that is not the target gets suppressed automatically, because suppressing it is what minimises output power. The array never needs to know where the jammer is. R̂ is estimated from snapshots with exponential forgetting, R̂(t) = λR̂(t−1) + (1−λ)xxᴴ, and that forgetting is the whole story of what follows.

How the predictive nuller works

predict runs MUSIC on the same R̂: it splits the covariance into signal and noise subspaces and scans the far-field grid for directions orthogonal to the noise subspace. That yields an explicit (θ, φ) for the jammer plus a presence flag, which lets it place a hard null at a chosen angle rather than waiting for energy to appear in R̂.

A finding that reframes the baseline: under a constant-power drifting jammer, predict is identical to lcmv — 55.0 versus 55.2 across the grid. Its predictive branch only engages around an on/off transition, and a constantly-present jammer never triggers it. The drift gap was never in its scope, which is exactly why the CV predictor was needed.

Method

The metric

One number per cell — the fraction of the run spent within 3 dB of the perfect-knowledge beamformer:

track_score = 100 · mean( (SINR_oracle − SINR) ≤ 3 dB )

It is normalised against what is achievable, which is what makes cells at different angles, arrays and power levels comparable. It folds convergence speed, steady-state gap and recovery into one figure, and the oracle scores exactly 100. Pass mark is 90.

The grid

3 arrays × 5 jammer positions × 3 scenarios × 3 seeds, each run against oracle plus the algorithms under test. Jammer positions are specified as angular separation from that array's target, not absolute angles, so the same five positions mean the same thing on every array. Every algorithm sees the same scenario, the same seed and the same oracle run, so a difference between rows is a difference between algorithms.

The test matrix. Seed-to-seed spread of the score was median 0.07 pp (p90 2.63, max 7.05), confirming 3 seeds is sufficient.

Result 2 — the diagnosis

Before building anything, the question was whether better angle knowledge would even help. The experiment: steer a hard null from scenario truth — something no algorithm may do — delayed by a variable number of steps, and see which delay reproduces the shipped tracker.

Two things follow. The drift deficit is an angle-lag deficit, so an angle predictor is the matching fix — and re-tuning λ is not, which agrees with the earlier sweep that found no λ where the failing cells pass. And the realistic target is ~95%, not 100%: grid quantization, finite null depth and weight smoothing set that ceiling.

The lag budget, and why the lead is derived rather than fitted

The MUSIC angle is computed from the same exponentially-forgotten R̂, so it inherits the same lag. Measured directly, the raw MUSIC estimate best matches truth delayed exactly 10 steps (mean error 0.27° at τ=10, rising either side). Adding the one-step application delay and the weight-smoothing lag:

lead_steps = 10 (covariance horizon) + 4 (application + smoothing) = 14

This gives a design rule rather than a magic number: the lead should track 1/(1−λ), and must be re-tuned if λ moves.

Result 3 — the fix

A constant-velocity Kalman filter on [θ, θ̇, φ, φ̇], fed by the MUSIC angle the algorithm already computes, extrapolated 14 steps ahead. While the jammer is both detected and moving, the null is aimed at the predicted angle.

Result 4 — the constraint that actually matters

Until this phase the simulator computed the desired-signal power from the same steering vector it handed the beamformer, so a calibration error could never appear. The milestone plan called this "the largest untested failure mode, and structurally untestable today." This campaign added an opt-in path that lets the engine propagate the true element patterns while the algorithm is handed assumed ones.

This is the classical MPDR signal-cancellation sensitivity: the snapshots contain the desired signal, so a mis-specified constraint direction causes the beamformer to null its own signal. The practical readings:

  • Usable region is below ~1° RMS per-element phase error.
  • The spread is enormous. At 2° the p10–p90 range is 1.1–76.8 — one array build could be fine and the next unusable. Any calibration statement needs a distribution, not a point.
  • This exposure is unchanged by the CV predictor. It is a larger risk to fielding than the gap this campaign closed.
Not a calibration test: data/spacing0.6_disturbed3 is a file-for-file counterpart to data/spacing0.6 and was the intended mismatch pair, but the two arrays differ grossly (steering coherence median 0.40, min 0.15) and every algorithm sits at 0.2%. It is a "wrong array" test, not a "mis-calibrated array" test. The parametric per-element model is the right instrument.

Result 5 — the stress axes

A second campaign perturbs one axis at a time so a failure is attributable: near-guard, near-endfire, a grating-lobe hunt, low signal, fast drift, and multi-cycle on/off. 46 cases, 414 runs, 0 failed case-seeds — and the first time any of these has been run with the predictor enabled.

The headline is a negative result, and it is the one worth having: across all 46 cells the predictor is never worse than the baseline — zero cells regress by more than half a point. Mean 87.3 → 91.3, cells passing 34 → 35 of 46.

Everything else is flat by design: the static, endfire, low-signal and grating-lobe cases move by 0.0 pp, because the speed gate keeps the predictor out of them. The grating-lobe hunt across 10–70° separation scores 89–99 throughout with no coverage hole, re-confirming that closed hypothesis under the new algorithm.

Findings

Seven findings, referenced by ID from the session log and the milestone plan.

F1new

ManyDipoles is exactly θ-mirror degenerate

e(θ,φ) ≡ e(180−θ,φ) — steering coherence 1.0000, whole-stack relative difference 2.8e-6. This is the textbook up/down ambiguity of a planar array in the z=0 plane with a common phase centre and no geometric phase re-added; the other two arrays have ground planes that break it (mirror coherence 0.85→0.08 and 0.87→0.53 over θ = 110→170).

It is benign for nulling — identical steering vectors mean a null at the mirror is the null at truth — but fatal for tracking, because the MUSIC peak hops branches and a naive filter differences the hops into a phantom velocity.

F2corrects a retraction

The 2026-09-06 front/back retraction measured the wrong angle pair

That note retracted a front/back-ambiguity diagnosis on the grounds that ManyDipoles has the lowest antipodal coherence of the three arrays (0.013). That is true — but the antipodal pair is (180−θ, φ+180), and the actual degeneracy is (180−θ, φ), a different pair. The ambiguity was real; the measurement that dismissed it was aimed at the wrong angles.

F3

The drift gap is angle lag of exactly one λ-horizon

A truth-steered null delayed 10 steps reproduces lcmv (49.8% / 3.88 dB vs 44.8% / 4.00 dB); 10 = 1/(1−λ). Perfect current-angle knowledge gives 94.8%. The covariance contributes almost nothing once the angle is known — the R = I and R = R̂ variants score within 0.6 pp of each other.

F4

MUSIC inherits the covariance lag, which is why the lead is 14

The raw MUSIC angle best matches truth delayed exactly 10 steps. The lead is therefore derived — 10 + 4 — not fitted. The optimum is genuinely drift-rate dependent (10 at 1°/s, 16–18 at 4°/s), so a single fixed value is a compromise; 14 has the best mean over 1/2/4°/s and is never worse than lcmv at any rate tested.

F5new capability

Calibration mismatch is the dominant deliverability risk

Usable below ~1° RMS phase error; at the floor by 3°. Verified sound: passing the true patterns as the assumed ones reproduces the unmodified run to max |ΔSINR| = 0.00e+00.

F6

The mirror fold auto-detects and rescues the DoA

The filter measures each array's own mirror coherence once at init — 1.0000 on ManyDipoles (fold on), 0.0505 on patchs (fold off) — with no configuration. On ManyDipoles the MUSIC DoA error against truth is median 139° raw, 1.5° modulo the fold. MUSIC was accurate all along; it was reporting the mirror branch. This also closes the open P8 item "DoA front-end untested on real element patterns."

F7

The residual failures are grid-limited, not algorithm-limited

On spacing0.6/sep45_th the DoA is perfect (median error 1.00°, presence 100%) and the lead sweep is flat and still climbing at L=24 — yet the cell scores 84.4% against a truth-steered ceiling of 98.3%. Fourteen points sit between a perfectly-steered null and one steered by a 1°-quantized angle. Three of the four other failures are on the 5°-grid array. The binding limit is angular resolution.

P9

Settled: adaptive and fixed diagonal loading are indistinguishable here

The open question from Phase P9, arbitrated on the headline metric: the paired difference is +0.00 pp on all 90 cells — exactly zero, every cell — and identically zero again across all 90 cells of the with-CV comparison. At this operating point loading_factor_db: 0 is a no-op, consistent with the config's own note that it reproduces the tuned ~10 dB in this regime. The choice can be made on simplicity; it should still be re-read at the high-σ_s corner P9 was built for, which this profile does not visit.

What to do to make this deliverable

Ordered by what most limits fielding, not by effort.

  1. Put a calibration tolerance in the specification

    The stack needs better than ~1° RMS per-element phase calibration, and degrades with enormous variance beyond it. This belongs in the interface contract with whoever builds and calibrates the array — today it is an undocumented assumption. Then extend the sweep to the other two arrays and to amplitude corners; only one array and one drift rate were measured.

    Blocking · spec + ~1 day of campaign

  2. Add robustness to steering error, and measure it on the same instrument

    The mismatch path built this phase makes the standard mitigations testable for the first time: worst-case-optimisation robust MVDR, or a diagonal-loading schedule tied to assumed steering uncertainty. This is the single highest-value algorithm work remaining, and it is worth more than further drift tuning.

    High value · moderate

  3. Interpolate the MUSIC peak sub-grid

    F7 shows the residual drift failures are angular-resolution limited. Parabolic interpolation on the pseudospectrum should recover much of the 14-point gap on high-DoF arrays — and the technique is already in-tree, used for the FFT period estimate in the same file. Expected to be nearly free.

    Cheap · likely closes 3–4 of the 4 remaining cells

  4. Make the predictor affordable

    MUSIC over the full far-field grid is 42×/126×/4.6× the reactive tracker. For a real-time build this needs a coarse-to-fine search or a gated update rate — striding the grid is the crude version and costs DoA accuracy (1.00° → 2.30° at stride 8), which F7 says is exactly the wrong thing to spend. Decide this before any hardware targeting.

    Blocking for real-time · moderate

  5. Declare the array's ambiguity explicitly

    A planar array with no geometric phase cannot tell up from down. That is a property of the geometry, not a bug, but it should be a declared field in the array configuration rather than something auto-detected from the pattern data at runtime — auto-detection is the right safety net, not the right contract.

    Cheap · reduces a whole class of confusion

  6. Retire availability as a headline number

    It reported 98.2% on cells scoring 20% against the achievable bound, and moved 0.05 pp for a 35-point real improvement. Keep it as a diagnostic; report oracle-tracking score.

    Free · documentation

  7. Close the remaining test debt before claiming coverage

    The Tier B stress axes are now done with the predictor on (Result 5). Still not run with it enabled: the amplitude sweep. Still untested anywhere: multiple simultaneous jammers and polarization mismatch — both outside the current scope, both plausible in the field. And guard_deg needs re-deriving per array: 5° is about 2× too optimistic on ManyDipoles.

    Reduced · amplitude sweep + a guard_deg re-derivation
