1 · Signal and array model

The array has N elements. Element patterns come from CST far-field exports on a (θ, φ) grid, so the steering vector is measured, not assumed — mutual coupling is included by construction, and there is no analytic exp(jkd sinθ) model anywhere in the signal path.

Write e(θ,φ) ∈ ℂN×nc for the stacked element responses at a direction, where nc is the number of polarization components retained (1 for a single-component export, 2 for total). A source at that direction excites all nc columns.

Per control step the receiver delivers K snapshots (default 128):

(1) x(t) = Σc ec(θs,φs)·sc(t) + Σc ec(θj,φj)·jc(t) + n(t) s, j, n i.i.d. circular complex Gaussian, drawn as sqrt(σ²/2)·(randn + i·randn) — temporally white σn² = 1 by definition; σs², σj² are set relative to it in dB

The interference-plus-noise covariance — the quantity the whole method is built around — is

(2) R = (σj²/nc)·e(θj,φj)·e(θj,φj)H + σn²·I note: interference + noise ONLY, no desired-signal term. This is the R of the MVDR oracle. What the ALGORITHM estimates from snapshots contains the desired signal too — that distinction (MVDR vs MPDR) drives §3 and §12.

Output SINR for a weight vector w, which is what everything is ultimately scored on:

(3) SINR(w) = σs²·‖wHe(θs)‖² / ( σj²·‖wHe(θj)‖² + σn²·‖w‖² ) the ‖w‖² term is per-element noise: it is why w cannot simply be scaled up
Scope, and what the algorithm may see. One jammer, unknown direction, 2-D (θ, φ). The algorithm consumes only the snapshot matrix X ∈ ℂN×K. The true θj never leaves the simulator; it is used solely to compute the oracle reference and the KPIs. Mode S — a scalar SINR feedback channel with no snapshots — is a separate contract not covered here.

2 · The beamformer

2.1 Rank-1 desired signal: MVDR

With a single polarization component the desired signal is rank-1 and the classical minimum-variance distortionless-response problem applies: minimise output power subject to unit gain on the steering direction.

(4) minimise wHR w subject to wHes = 1 ⇒ w = R-1es / ( esHR-1es )

The constraint pins the desired direction, so the only way the optimiser can reduce output power is to attenuate everything else that is loud — which places a null on the jammer without ever estimating its direction. This is why the reactive path needs no DoA at all.

2.2 Adding an explicit null: LCMV

To place a null at a chosen direction (the predictive path does this), extend to a linear-constraint set: distortionless on es, zero on each column of enull.

(5) C = [ es , enull ] , g = [ 1 , 0 , … , 0 ]T w = Rl-1C · ( CHRl-1C )+ · g Rl = R + δI pinv, not inverse: if a predicted null direction happens to coincide with the steering direction, C goes rank-deficient. pinv degrades to a minimum-norm solution instead of throwing a warning and returning garbage.

2.3 Rank-r desired signal: max-SINR

With nc = 2 a distortionless constraint on every component is over-constrained — the desired signal is rank-nc, and demanding unit gain on each column fixes the polarization response rather than the power. The correct object is the generalised Rayleigh quotient:

(6) maximise wH(esesH)w / wHRlw A = Rl-1es (N × r) G = esHA (r × r) Hermitian gram w = A · vmax(G) v_max = principal eigenvector; w normalised to unit norm with a hard null, first restrict to the null-constrained subspace: Q = null(enullH) , then solve the same problem in Q and map back w = Qz
Why this matters for generality. Which branch runs depends on nc, which depends on the export. An array whose second component is numerical residue (~100 dB down) must be treated as single-polarization: pairing a real component with noise makes nc = 2 while each physical source is rank-1, which corrupts the model order used in §5 and §6. select_polarization_stacks hard-errors on that pairing rather than letting it through.

3 · Diagonal loading

Every solve above uses Rl = R + δI. Loading is not a numerical nicety — it is the physical knob that trades null depth against main-beam gain and robustness, and it appears again in §10 as the mechanism of the graded release.

The estimated covariance contains the desired signal (this is MPDR, not MVDR), so under any steering error the optimiser can reduce output power by nulling the signal itself. Loading bounds how sharply it can do that. Empirically δ = +10 dB relative to the noise floor; at −10 dB the self-nulling cost 2–3.7 dB of oracle gap, and above the jammer eigenvalue (≈ J/N + 10log₁₀N) the null is starved instead.

Defect found and fixed. A data-driven loading mode estimated δ from the data and required N > 2nc, throwing otherwise. That made the entire Mode C stack — including the reactive tracker, which does not use the feature — unable to run on a 1-element or a 2-element dual-pol array. Measured across 90 campaign cells the mode was worth +0.00 pp against fixed loading: identically zero on every cell. It now warns and falls back to the configured δ.

4 · Covariance estimation, and the lag it creates

Per step, the K snapshots are batched and folded into a running estimate with exponential forgetting:

(7) R̂batch(k) = (1/K)·X(k)X(k)H R̂(k) = λ·R̂(k−1) + (1−λ)·R̂batch(k) λ = 0.90, R̂(0) = I effective memory ≈ 1/(1−λ) = 10 steps = 0.5 s at dt = 0.05 s

One batch per step, not one update per snapshot column — the earlier per-column recursion silently made K an accelerator of forgetting rather than a noise-reduction knob.

4.1 The lag is exactly one horizon

Under a jammer drifting at θ̇, the exponentially-weighted estimate is centred on the jammer's position roughly 1/(1−λ) steps in the past. This was measured rather than assumed: steering a hard null from ground truth, delayed by τ steps, reproduces the reactive tracker's score at τ ≈ 10.

5 · MUSIC direction finding

Eigendecompose the Hermitian part of R̂, sort descending, and split into signal and noise subspaces at an assumed model order:

(8) R̂ = V Λ VH , λ1 ≥ λ2 ≥ … ≥ λN nsig = 2·nc desired signal (n_c) + one jammer (n_c) En = V[:, nsig+1 : N] noise subspace P(θ,φ) = ‖a(θ,φ)‖² / ‖EnHa(θ,φ)‖² summed over components

The ‖a‖² numerator is essential with measured element patterns. A textbook ULA has constant steering-vector norm, so the numerator is a constant and is usually dropped. Real exports do not: column norms vary strongly across the grid, and without normalisation the metric peaks at low-norm directions (endfire) rather than at sources.

The grid search excludes a guard sector around the target (§11) and is thinned by doa_stride. Cost is the dominant term in the whole algorithm: at full resolution this is 42× / 126× / 4.6× the reactive tracker on the 6-, 16- and 20-element arrays. Striding halves it for a DoA RMSE change of 1.00 → 1.45° at stride 4.

Two model-order problems, one fixed and one open. Fixed: nsig ≥ N leaves no noise subspace, so MUSIC genuinely cannot run — but it used to throw, killing the whole run on small apertures. It now returns feasible = false and the caller degrades to the reactive beamformer. Open: nsig = 2nc is an assumption, not a measurement. On an array whose second component is weak but real it reads presence off a near-noise eigenvalue. A rank-aware order estimated from the eigenvalue profile is the standing recommendation.

6 · Presence detection, and the two-timescale fix

Whether the jammer is currently transmitting is read from the signal/noise eigengap. The first jammer eigenvalue sits at index nc+1; when the jammer stops it collapses toward the noise floor.

(9) σ̂n² = mean( λnsig+1 … λN ) noise-subspace mean gapdB = 10·log₁₀( λnc+1 / σ̂n² ) present ⟺ gapdB ≥ presence_gap_db default 6 dB

6.1 Why this failed, and the fix

Evaluated on R̂, this statistic inherits R̂'s smoothing. With a 0.5 s memory and a 1–2.5 s OFF phase, residual jammer energy keeps the eigengap open through the entire gap: presence saturates at 100%. And a constant indicator has no spectral line, so the period estimator of §7 can never learn anything.

One forgetting factor cannot serve both roles. The beamformer wants long memory for low variance; the edge detector wants short memory for time resolution. The repair maintains a second covariance used only for detection, never to form weights:

(10) R̂fast(k) = λf·R̂fast(k−1) + (1−λf)·R̂batch(k) λf = 0.5 → ~2-step memory present ← eigengap test (9) evaluated on R̂fast angle ← MUSIC (8) evaluated on R̂ the angle still wants averaging constraint enforced at init: λf < λ. A detector slower than the beamformer cannot resolve edges the beamformer already smooths.

7 · Period estimation and anticipatory nulling

The presence indicator is recorded as a 0/1 sequence and its dominant non-DC spectral line is taken as the toggle period.

(11) p = presence record, last B samples ; P = |FFT(p − mean p)|² bin* = argmax P[2 … ⌊n/2⌋+1] trusted ⟺ P[bin*] > 3·mean(P[2…]) AND n ≥ min_periods · period sub-bin parabolic interpolation on (P[b−1], P[b], P[b+1]): δ = ½(a−c)/(a−2b+c) , period = n/(bin*−1+δ) the bin grid is coarse (period = n/bin), and a raw bin is off by enough steps to mistime the pre-null.
Defect: the window could not hold the periods of interest. With B = 1024 steps = 51.2 s and min_periods = 3, the trust condition n ≥ 3·period can only be met for periods below ~17 s. Every slower pattern was undetectable by arithmetic, regardless of how clean the signal was. The window is now sized from the longest period worth detecting: B = max(Bcfg, ⌈min_periods · Tmax / dt⌉).

When the period is trusted and the jammer is currently absent, the next turn-on is projected and the null is pre-formed L steps before it:

(12) φ = (k − klast_on) mod T̂ ; steps_to_next = T̂ − φ L = clamp( lead_frac · T̂ , lead_steps , lead_cap_horizons/(1−λ) ) predicted_on ⟺ steps_to_next ≤ L

Both bounds are load-bearing. A fixed lead is a shrinking fraction of a lengthening cycle — the shipped 6 steps pre-nulled for 0.75% of a 40 s OFF window. The cap exists because the useful lead is bounded by re-acquisition time, not by cycle length: uncapped, scaling with the period cost −2.5 pp at 40 s; capped at two covariance horizons it gains +5.6.

8 · Constant-velocity DoA prediction

To remove the lag quantified in §4.1, the MUSIC angle sequence drives a Kalman filter with a constant-velocity model on (θ, φ) in degrees.

(13) x = [ θ , θ̇ , φ , φ̇ ]T F = [1 dt 0 0 Qblk = q·[ dt⁴/4 dt³/2 H = [1 0 0 0 0 1 0 0 dt³/2 dt² ] 0 0 1 0] 0 0 1 dt 0 0 0 1] Q = blkdiag(Qblk, Qblk) , q = qaccel² Rmeas = diag(r², r²) r = DoA noise std, grid-quantization dominated

Standard predict/update, with three domain-specific departures:

  1. Azimuth innovation is wrapped to [−180°, 180°). Without it a jammer crossing φ = 0 produces a 359° residual and the gate discards a perfectly good measurement.
  2. Innovation gating. If ‖y‖ > gate_deg the measurement is rejected and the state coasts on the model. After max_misses consecutive rejections the track is dropped, so a stale velocity cannot steer the null indefinitely.
  3. Pole reflection. A predicted θ outside [0°, 180°] is reflected back with φ → φ+180° — the same fold the sphere applies, not a clamp.

8.1 The lead is derived, not fitted

The prediction is extrapolated Lcv steps ahead. That value is not tuned: the MUSIC angle is computed from the same lagged R̂, so it inherits the covariance horizon. Measured directly, the raw MUSIC estimate best matches truth delayed exactly 10 steps (mean |err| 0.27° at τ=10, rising either side). Adding the one-step application delay and the weight-smoothing lag:

(14) Lcv = 1/(1−λ) + (application + smoothing) = 10 + 4 = 14 steps design rule: Lcv tracks 1/(1−λ). Re-tune it if λ moves.

8.2 The engagement gate

The predicted angle steers a hard null (5) with the measured R̂ only when the track is valid and the estimated angular speed exceeds a threshold:

(15) speed = hypot( θ̇ , φ̇ · sin θ ) great-circle rate valid ⟺ ntrack ≥ min_track_steps AND speed ≥ min_speed_deg_s
Why the gate is the important part. Below the speed threshold the reactive path is already at the oracle and there is nothing to win. With the gate, static and on/off scenarios were measured bit-identical with the feature on and off — max |ΔSINR| < 1e-12 — so the CV path is a strict addition rather than a change. Measured effect where it does engage: 2°/s drift 44.8 → 90.3%; drift with a 10° jump 36.6 → 86.7%.

9 · The mirror ambiguity

Some exported arrays are exactly degenerate under (θ,φ) → (180−θ,φ). Measured on a 20-element planar dipole array: steering coherence 1.0000, whole-stack relative difference 2.8×10⁻⁶. This is the textbook up/down ambiguity of a planar array in the z=0 plane with a common phase centre and no geometric phase re-added.

It pulls two ways:

  • Benign for nulling. If e(θ) ≡ e(180−θ), a null at the mirror is the null at truth. The reactive path, which never uses an angle, is entirely unaffected.
  • Fatal for tracking. The MUSIC peak hops between branches, and a CV filter differences the hops into a large phantom velocity — worse than having no predictor.

So the filter measures the array's own mirror coherence once at initialisation, over a few probe directions, and takes the minimum. Above 0.99 the fold is enabled and each measurement is resolved to whichever branch is nearer the current prediction.

(16) coh = |a(θ,φ)Ha(180−θ,φ)| / (‖a(θ,φ)‖·‖a(180−θ,φ)‖) fold ⟺ min over probes( coh ) > 0.99 z = argmin{z, mirror(z)} ‖ z − Hx̂− ‖ nearest-branch resolution
Consequences worth recording. The threshold is not near anything — the arrays in the set split into 1.0000 versus 0.05–0.87. Measured modulo the fold, the DoA error on the degenerate array falls from median 139° to 1.5°: MUSIC was accurate all along and reporting from the wrong hemisphere. Note also that any DoA-error KPI on such an array is meaningless unless computed modulo the fold — and that θ = 90° is its own mirror, so the coherence test is vacuous there and returns NaN.

10 · Release policy, and why the question is closed

When presence goes false, should the null be dropped? Releasing restores full quiescent gain — the point of detecting OFF at all. But the null must be re-acquired at the next turn-on, at a cost of roughly one covariance horizon of degraded SINR.

Three policies were implemented and measured at scale.

10.1 Binary (shipped)

Release immediately on ¬present: recompute from R = I, giving the quiescent beam.

10.2 Elapsed-absence gate (rejected)

Release only after sabsent ≥ h/(1−λ). Deliberately causal and learning-free — an earlier version gated on T̂(1−duty) and did nothing useful, because min_periods cycles of learning consume most of a short run and the damage is done before a period exists.

10.3 Graded release via loading (rejected)

Relax the null continuously rather than switching. The relaxation is applied through diagonal loading — the physical knob of §3 — because raising δ toward the scale of R̂'s own energy progressively swamps the jammer eigenvalue and returns the beam to quiescent. Blending two weight vectors was rejected: they are defined only up to a phase and can cancel.

(17) α(sabsent) = 0 if s ≤ t0 (s − t0)/(t1 − t0) if t0 < s < t1 1 if s ≥ t1 t0 = hmin/(1−λ) , t1 = max( t0 + hramp/(1−λ) , foff·T̂(1−duty) ) δeff = δ · ( max(κ·tr R̂, δ)/δ )α geometric ramp to a swamping load t1 scales to the PREDICTED OFF window once the period is learned: short when the gap is long (release early, keep the gain), never completing when the gap is short (hold the null, avoid re-acquisition) — behaviour a single constant provably cannot provide. tr R̂ upper-bounds the largest eigenvalue at O(N) instead of an eigendecomposition.

A NaN trap this exposed. With the feature block absent the ramp fields are NaN, and NaN ≤ 0 is false — so the ramp arithmetic ran on NaN, δ went NaN, and the solve turned singular. The run completed, silently returning garbage (a 25 s cell read 12.8 instead of 88.2). The guard is now an explicit finiteness test, and a gate asserts that an un-repaired run yields finite SINR and finite weights at every step.

11 · Array profiling, derived guard, feasibility

Several constants were calibrated once on one array and do not generalise. They are now derived per (array, target) from the pattern data itself.

(18) wq = quiescent beam (4) with R = I D(θs) = 10log₁₀[ P(θs,φs) / ⟨P⟩Ω ] ⟨·⟩Ω = solid-angle-weighted mean, sinθ HPBW = −3 dB width of P through the target, in θ and in φ guard = max( ½·max(HPBWθ, HPBWφ) , grid step )

The guard is half the wider beamwidth: the angular distance at which a source stops being in the main beam. Against the shipped global constant of 5°, the derived value spans 16° to 72.5° across the arrays — so the constant was wrong on every one of them, and any earlier result whose jammer sat between the true and assumed guard was measuring a main-beam jammer, out of scope by the milestone's own definition.

The same profile decides whether a cell is a test at all. A pair is refused if the array has no gain toward the target (D < 0 dBi) or if its main beam covers so much of the sphere that no jammer position lies outside it (guard > 90°). In the campaign 11 of 35 pairs were refused with a stated reason — including all five targets on the 1-element array.

12 · The metric

Scoring across arrays of 1 to 20 elements needs normalisation against what each array can physically achieve, not against an absolute target.

(19) woracle(k) = MVDR (4) using the ANALYTIC R of (2), applied with one step of lag track_score = 100 · meank[ SINRoracle(k) − SINR(k) ≤ 3 dB ]

The oracle scores exactly 100 by construction, giving every grid a built-in anchor. The score folds convergence speed, steady-state gap and recovery into one number.

Two cautions on reading it. First, a high score is not good absolute performance. A 2-element array scores 99 because its achievable SINR is 11 dB; a 16-element array scores 72 against an achievable 31 dB. Score and potential must always be reported together. Second, availability is not a substitute. On the drift campaign a 35-point improvement in track score moved availability by +0.05 pp (98.18 → 98.23) — it saturates on easy cells and cannot rank algorithms.

12.1 What actually limits the system

The simulator computes the desired-signal power from the same es handed to the beamformer, so steering-vector error was structurally unmeasurable until an opt-in assumed-patterns path was added. With per-element calibration error gn = exp(jεn), ε ~ N(0, σφ²):

13 · The full update, in order

One control step of the predictive Mode C algorithm. Every branch and its governing section:

  1. Fold snapshots. Batch to R̂batch, update R̂ (7) and, if enabled, R̂fast (10).
  2. Feasibility. If 2nc ≥ N, MUSIC cannot run: emit the reactive solution and return (§5).
  3. Angle. MUSIC on R̂ (8), restricted outside the derived guard (18).
  4. Presence. Eigengap (9) on R̂fast when enabled, else on R̂. Update the absence counter and the presence record.
  5. Period. Periodogram (11); if trusted, project the next turn-on and evaluate the lead (12).
  6. CV filter. Predict, mirror-fold (16), gate, update; extrapolate Lcv ahead (13)–(14).
  7. Branch, in this order:
    • present and CV valid → hard null (5) at the predicted angle, with R̂
    • present → reactive (4)/(6) with R̂
    • absent, return predicted → pre-null at last known angle, with R = I
    • absent → release policy (§10): quiescent, or the graded load (17)
  8. Smooth and apply.

13.1 Weight smoothing

Solutions from (4)–(6) are defined only up to a unit-modulus phase, so a naive blend of two representations of the same beam can destructively interfere. The global phase is aligned first:

(20) ρ = wprevHwtarget / |wprevHwtarget| w = (1−μ)·wprev + μ·(wtarget·ρ*) , then w ← w/‖w‖ μ = 0.25

μ trades smoothness against reactivity and contributes ~3–4 steps to the lag budget of (14). It is itself a measurable drift cost — the reactive tracker alone goes 44.8 → 55.4 → 59.1% as μ goes 0.25 → 0.5 → 1.0 — but it was tuned for other scenarios and is left alone; the interaction is recorded rather than exploited.

The applied weights are used at step k+1: this step's capture cannot be filtered by weights derived from itself. That one-step delay is the "+1" inside the "+4" of (14).

Open items in the algorithm itself

  • MUSIC model order is hardcoded at 2nc (§5). A rank-aware estimate from the eigenvalue profile would remove a class of array-specific failures.
  • Calibration robustness (§12.1) is untreated. Worst-case-optimisation robust MVDR, or a loading schedule tied to assumed steering uncertainty, is the highest-value remaining algorithm work.
  • MUSIC cost (§5) is 42–126× the reactive path. A coarse-to-fine search or a gated update rate is required before real-time targeting; striding is the crude version and costs exactly the angular precision that limits the residual failures.
  • guard_deg (§11) is derived in the test harness but still a global constant in the shipped configuration.
  • Drift beyond ~10°/s — the CV predictor extends the envelope without removing the limit.
  • Out of scope entirely: multiple simultaneous jammers, and polarization mismatch between the jammer and the assumed model.
